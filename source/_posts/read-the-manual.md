# 手册

手册基本都是英文的，如果英文不好的话就只能借助翻译器了，阅读体验相对会差一点。不过这也相当于是一份优质的技术英语阅读理解语料（

---

在类 Unix 系统中，几乎没有哪一个命令会不附带手册。

手册是个好东西，基本每个命令行软件都会具备，它是最权威的官方教程，会详细描述命令的参数、作用，有的还附有实例。针对一个陌生的命令行软件，阅读它的手册通常是第一选择。尤其是对于一些难以寻得教程的软件，阅读手册几乎是唯一的选择。

可以被称作手册的文档有很多，例如 man 手册、info 手册，亦或是以网页形式发布的也可被称作手册。不过他们一般都满足如下特征：

1. 语言简洁清晰
2. 段落划分清楚
3. 包含语法解释
4. 内容丰富完整

在常规的 Linux 发行版下，一般都预装了 man-pages 手册和 man 阅读程序。在通过包管理器安装命令时，包管理器会自动更新对应的手册。

# man 手册

man 手册是最常见的一种手册，其特点是单页，段落清晰。以 man 命令的手册为例，它分为 NAME（名称）、SYNOPSIS（语法）、DESCRIPTION（介绍）、EXAMPLES（示例）、OVERVIEW（概览）、OPTIONS（参数）、SEE ALSO（另见）、...... 部分，这些列举出来的部分大部分软件都具备，通过阅读相应的段落很快就能了解这个命令。

通常而言，阅读一份 man 手册来学习陌生命令的流程是这样的：

1. 通读 NAME、DESCRIPTION 以了解重要的定义、概念和用途
2. 根据需要，在 OPTIONS 搜索相应的参数

阅读 man 手册的流程对于不同的软件相异，善用搜索功能能够很好地节省时间。

## 搜索手册页

使用 `man -k <关键词>` 进行搜索。这里的关键词需要是英文，并且搜索是基于文本匹配的，不要期望有搜索引擎那么智能。

## 阅读方式

man 手册拥有很多阅读器：

1. man 命令
2. info 命令
3. vim man 插件
4. 其他第三方阅读器
5. 浏览器

首先是 man 命令，它实际上是使用 less 来展示内容的，操作方式也与 less 相同，按 H 进入操作指南。

然后是 info 命令，虽然 info 命令是用来阅读 info 手册的，但是对于没有 info 手册的命令，info 会回退到对应的 man 手册。

如果想要拥有更强大的功能并且熟悉 vim 的话，可以考虑 vim 的 man 插件。插件启用方式参见 `:help man`，在 .vimrc 文件中加入 `runtime ftplugin/man.vim` 即可。之后使用 `:Man <命令>` 就可以查看命令对应的手册了。

第三方阅读器我没怎么使用过，暂不做评价。

最后是浏览器。man 手册是可以通过浏览器阅读的，图形化界面方便上手。在正上方附有目录可快速跳转。对于不想折腾的人是个好选择。使用方法是 `man -H<浏览器> <命令>`，注意这里 `-H` 和浏览器名称之间不能有空格。

# info 手册

man 手册有一个通病：所有信息平铺在眼前，阅读和理解有一定难度。

info 手册正是解决这种痛点的，它采用树状结构组织文档，每一个节点之间采用超链接相连。可以方便的在父子节点和兄弟节点之间进行导航。

拥有 info 手册的软件主要是 GNU 系列的，其他软件似乎具有的很少。

info 手册需要手动安装，用包管理器安装即可。

## 阅读方式

使用 `info <命令>` 进行阅读手册。按 h 打开帮助，方向键导航，Tab、Shift+Tab 在各个超链接之间跳转，Enter 打开超链接。可以使用 `info info` 学习 info 本身。使用一会儿就可以发现，info 手册更加适合学习一个命令，而 man 手册更适合忘记参数的时候快速查询。

info 命令具有很多快捷键，支持多窗口浏览，自定义快捷键，执行命令等功能，非常强大。详情参见 `info info`。

# tldr 手册

TL;DR = Too Long; Don't Read

顾名思义，这是一个精简的手册，聚焦常用功能，主要面向命令初学者，其中拥有大量的示例，由第三方社区维护。

它拥有很多不同语言编写的客户端。默认的是 Python，还有 Rust 的 tlrc 版本和 Node.js 版本。社区还有 Go、C/C++ 甚至 Bash 版本。

使用方法：`tldr <命令>` 查看相关页面，`tldr --search <命令>` 搜索页面，`tldr --update` 同步缓存。可以使用 `tldr --language zh` 切换至中文，大部分主流命令已拥有中文的 tldr 文档。
